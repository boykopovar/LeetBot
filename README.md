# LeetBot

Telegram-бот, который принимает входящие письма на произвольный email-адрес и пересылает их пользователю в Telegram в виде HTML-документа. Встроенный SMTP-сервер, никаких сторонних почтовых сервисов.

---

## Как это работает

```
Внешний отправитель
        |
        v
  SMTP-сервер (aiosmtpd)
        |
   handle_RCPT: есть ли активная сессия на этот адрес?
        | нет: 550 No such user
        | да:  250 OK
        v
   handle_DATA: парсинг письма
        |  subject: имя файла
        |  HTML-часть (или plain, обёртка в <pre>)
        |  caption: отправитель, IP, время
        v
   bot.send_document() -- Telegram-чат пользователя
```

1. Пользователь запрашивает адрес командой `/random` или кидает в чат уже известный ему адрес из своего множества.
2. Бот регистрирует пару `user_id / email` в `SessionRegistry` и запускает таймер на `SESSION_MINUTES` минут.
3. Пока сессия активна, любое письмо, пришедшее на этот адрес, немедленно пересылается пользователю.
4. По истечении таймера сессия удаляется; повторная активация - снова `/random` или тот же адрес вручную.

## Алгоритм выдачи адресов: гарантированное непересечение

### Суть задачи

Каждый пользователь должен получить **своё личное подмножество адресов**, которое:
- не пересекается ни с одним другим пользователем;
- бот сам может за константное время проверить, принадлежит ли произвольный адрес конкретному пользователю;
- не требует базы данных - никакого хранилища назначенных адресов нет.

### Что такое биекция и зачем она нужна

Feistel-шифр - это **биекция** (взаимно однозначное соответствие) на множестве целых чисел `[0, N)`.

Биекция означает: каждому входному числу соответствует **ровно одно** выходное, и каждое выходное число происходит **ровно от одного** входного. Это не хэш (там нет обратного пути) и не случайная функция (там могут быть коллизии). Feistel-шифр обратим по определению.

Из этого следует ключевое свойство: шифр **разбивает** всё пространство `[0, N)` на непересекающиеся подмножества строго по структуре входного числа - без коллизий, без хранения, детерминированно.

### Пространство чисел

```
inp = user_id x 65536 + nonce
```

- `user_id` - Telegram ID пользователя (уникален глобально)
- `nonce` - случайное 16-битное число (0..65535), генерируется при каждом `/random`

Все возможные значения `inp` образуют **непересекающиеся полосы** по `user_id`:

```
user 111: [111 x 65536 + 0 .. 111 x 65536 + 65535]
user 222: [222 x 65536 + 0 .. 222 x 65536 + 65535]
user 333: [333 x 65536 + 0 .. 333 x 65536 + 65535]
```

Полосы разных пользователей не пересекаются **никогда**.
### Шифрование: Feistel-сеть

```python
_feistel_encrypt(key: bytes, value: int) -> int
```

Feistel-сеть с 8 раундами на сбалансированных половинах:

- Пространство `[0, N^7)` (≈ 1.7 × 10¹⁵) делится на две половины:
  - `_HALF_LOW = N^3 = 150^3 = 3 375 000`
  - `_HALF_HIGH = N^4 = 150^4 = 506 250 000`
- Раундовый ключ: `BLAKE2b(master_key || round_byte)` - для каждого раунда свой
- PRF: `BLAKE2b(val, key=round_key)`, 8 байт, `% mod`
- Нечётные раунды работают с `_HALF_LOW`, чётные с `_HALF_HIGH`

Результат: биективное отображение `inp` на `encrypted`, работающее на всём пространстве `[0, _HALF_LOW x _HALF_HIGH)`.

### Кодирование в строку

Зашифрованное число кодируется в **7 слогов** из алфавита 150 слогов (2- и 3-буквенных):

```python
_encode(value) -> str   # 7 позиций × log₁₅₀, строка 14-21 символов
```

Это базирование числа в системе счисления с основанием 150, где цифры - слоги. Строка произносима и не похожа на случайный набор букв.

### Верификация (обратный путь)

```python
belongs_to_user(key, user_id, local) -> bool:
    decoded = _decode(local)                    # строка в число
    decrypted = _feistel_decrypt(key, decoded)  # число в inp
    return decrypted // 65536 == user_id        # старшие биты - это user_id?
```

Никакой базы данных. Бот просто расшифровывает локальную часть адреса и смотрит, чей `user_id` в ней закодирован.

### Что именно гарантирует система

1. **Непересечение множеств адресов разных пользователей.**
   Входные числа для разных `user_id` лежат в строго непересекающихся диапазонах. Feistel - биекция, она не создаёт коллизий. Следовательно, выходные числа (а значит, и адреса) двух разных пользователей тоже никогда не совпадут.

2. **Детерминированная верификация без хранилища.**
   Бот в любой момент может проверить любой адрес: расшифровать и извлечь `user_id`. Не нужно хранить список выданных адресов. Всё вычисляется из самого адреса.

3. **Пользователь не может активировать чужой адрес.**
   При вводе адреса вручную бот вызывает `belongs_to_user`. Если адрес чужой - отказ с сообщением `❌ Этот адрес не из вашего множества`. Администраторы из `ADMIN_IDS` обходят эту проверку.

4. **Адрес нельзя угадать или сконструировать без ключа.**
   `ENCRYPT_KEY` - 32-байтный секрет. Без него Feistel-шифр непрозрачен: связь между `user_id` и выдаваемыми адресами не видна снаружи. Знание одного адреса не даёт информации о других.

5. **Повторная выдача всегда в том же множестве.**
   Каждый вызов `/random` берёт новый случайный nonce, но `user_id` фиксирован. Все выданные адреса принадлежат одному и тому же непересекающемуся диапазону пользователя.

### Сколько адресов у одного пользователя

Nonce - 16-битное число: `2^16 = 65 536` значений.

Каждому значению nonce соответствует **ровно один** адрес, не совпадающий ни с каким другим. Итого у каждого пользователя **65 536 различных адресов**.

Общее пространство адресов: `150^7 = 1 708 593 750 000 000` (≈ 1.7 квадриллиона).
Максимум пользователей без коллизий: `1 708 593 750 000 000 / 65 536 ≈ 26 071 071 624` (26 миллиардов).

### Повторный вызов своих адресов

Пользователь может **скинуть в чат любой ранее полученный адрес** (локальную часть или полный `local@domain`) - бот верифицирует принадлежность через `belongs_to_user` и активирует сессию заново. Это работает для любого из 65 536 адресов пользователя, сколько угодно раз.

## Установка

### Зависимости

```
Python 3.8+
aiogram >= 3.0
aiosmtpd
email-validator
python-dotenv
```

```bash
pip install aiogram aiosmtpd email-validator python-dotenv
```

### Конфигурация

При первом запуске создаётся `.env` с дефолтными значениями. Обязательные поля:

```env
BOT_TOKEN=<токен от @BotFather>
ENABLED_IDS=<telegram_id через пробел, кому разрешён доступ>
DOMAIN=<домен, на который принимаются письма>
```

Опциональные поля:

```env
SMTP_HOST=0.0.0.0          # адрес прослушивания SMTP
SMTP_PORT=25               # порт SMTP
SESSION_MINUTES=5          # время жизни сессии
LOG_FILE=LeetBot.log       # файл для WARNING+ логов
ENCRYPT_KEY=               # hex-ключ 32 байта; генерируется автоматически если пуст
ADMIN_IDS=                 # telegram_id администраторов через пробел
```

> `ENCRYPT_KEY` генерируется один раз и сохраняется в `.env` автоматически. Смена ключа делает все ранее выданные адреса недействительными - бот перестанет их верифицировать.

### Запуск

```bash
python main.py
```

SMTP и Telegram polling стартуют одновременно в одном asyncio event loop.

## Команды

| Команда / ввод | Действие                                                                      |
|----------------|-------------------------------------------------------------------------------|
| `/random`      | Генерирует новый адрес из множества пользователя, активирует сессию           |
| `localpart`    | Активирует сессию на `localpart@DOMAIN` (если адрес принадлежит пользователю) |
| `local@domain` | То же, с явным доменом                                                        |

## Логирование

- **stdout / INFO**: каждый Telegram-апдейт с user_id, именем, контентом и временем обработки; события SMTP (accepted / rejected / delivered).
- **Файл / WARNING+**: только ошибки и предупреждения.
- Внутренние логи `aiosmtpd` подавляются фильтром `_DropAll`.
