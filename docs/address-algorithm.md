# Алгоритм выдачи адресов

## Что это даёт

Каждый пользователь получает **2 097 152 непересекающихся адреса**. Ключевое слово - непересекающихся: адреса двух разных пользователей никогда не совпадают, и это гарантируется математически, а не таблицей в базе данных.

Из этого следуют три практических свойства:

**Изоляция без координации.** Бот не ведёт реестр «кому какие адреса выданы». Пространство адресов каждого пользователя определяется его `user_id` и секретным ключом сервера - два пользователя никогда не получат одинаковый адрес, даже если попросят одновременно.

**Мгновенная верификация владельца.** Когда пользователь вводит адрес вручную, бот не делает запрос в хранилище - он просто расшифровывает адрес и проверяет, что внутри зашит именно этот `user_id`. Подделать такой адрес без знания серверного ключа невозможно.

**Произносимые адреса.** Адреса кодируются слогами (`gotimasabu@…`), а не случайным набором букв и цифр.

---

## Как это работает

Каждый пользователь получает **2 097 152 непересекающихся адреса**, детерминированно вычисляемых из `user_id` без базы данных.

```
inp = user_id * 2097152 + nonce   (nonce - случайное 21-битное число)
```

`inp` шифруется 8-раундовой Feistel-сетью с ключом `ENCRYPT_KEY` и кодируется в 8 слогов из алфавита 150 слогов (строка 16–24 символов).

Верификация адреса - расшифровка и проверка `decrypted // 2097152 == user_id`.

Общее пространство: `150^8 ≈ 2.56 × 10^17` адресов, максимум ~122 млрд пользователей без коллизий.

Если `user_id` выходит за пределы допустимого диапазона, генерация адреса невозможна - бот сообщит об этом в чат.
